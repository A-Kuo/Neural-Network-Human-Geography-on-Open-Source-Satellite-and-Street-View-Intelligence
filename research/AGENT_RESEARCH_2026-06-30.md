## Summary
Geospatial ML shifted decisively toward multimodal foundation models in 2025: instead of training a single CNN per data source, current SOTA fuses satellite imagery, street-view panoramas, POI/OSM data, and raw coordinates through modality-specific encoders into a shared embedding space, trained contrastively or via masked reconstruction. For this repo, the actionable shift is from "classify a scene" to "learn a general-purpose location embedding" that downstream tasks (socioeconomic prediction, land-use classification, change detection) can regress against — mirroring how CLIP-style pretraining replaced task-specific vision models.

## Engineering Insights
- Preprocess satellite tiles and street-view frames on the same pipeline stage: cloud-mask + reproject satellite tiles and standardize street-view FOV/exposure before either hits the encoder, so both modalities enter fusion at comparable quality.
- Preserve CRS (coordinate reference system) end-to-end — losing it between ingestion and inference is the most common bug reported in geospatial MLOps writeups and silently misaligns satellite/street-view pairs.
- Use geographic (spatial block) cross-validation, not random splits — nearby tiles are spatially autocorrelated, so random CV overstates generalization.
- Design for missing modalities at inference time (e.g., a location with satellite coverage but no street-view imagery); UrbanFusion's random token masking during training is a direct, implementable pattern for this.
- Batch inference over Dask/Rasterio-style tiled processing scales far better than per-image inference loops once the repo moves past demo-scale imagery counts.

## Recommended Next Actions
1. Add a location-embedding baseline: wrap a pretrained SatCLIP/GeoCLIP-style encoder (or train a small contrastive encoder on repo's own satellite+street-view pairs) and expose it as a reusable `embed_location()` function other repo modules can call.
2. Implement spatial block cross-validation in the repo's eval harness to replace any random train/test split, and report both random-split and spatial-block metrics side by side to expose overfitting to spatial autocorrelation.
3. Add an OSM ingestion module (roads/land-use tags via Overpass API or a static extract) as a lightweight third modality per GeoLink's approach — no new imagery labeling required, and it's a natural extension of the "open-source" framing already in the repo name.

## Security Notes
- Street-view and satellite pipelines commonly hit third-party APIs (Google Street View, Mapbox, Sentinel Hub) that require API keys — none of the reviewed projects embedded keys in source; all used environment variables or `.env` files excluded via `.gitignore`. Verify this repo's `.gitignore` covers any imagery-API credentials before adding new data-source integrations.
- OSM/Overpass ingestion (recommended action #3) pulls from a public, unauthenticated API — no credential risk, but add request rate-limiting to avoid IP bans, consistent with the "production deployment" guidance found in this cycle's search results.
